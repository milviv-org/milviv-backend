# 1. Introduction and Goals

## 1.1 Обзор требований

### Назначение системы

Система предназначена для управления личными целями, проектами, задачами и привычками пользователя с использованием игровых механик мотивации.

Пользователь формирует цели, декомпозирует их на проекты и задачи, планирует выполнение, устанавливает сроки и сложность задач. После выполнения задач пользователь получает баллы в зависимости от их сложности и может потратить накопленные баллы на заранее созданные награды.

Основная цель системы — повысить мотивацию пользователя к выполнению задач за счёт формирования цепочки:

**Цель → Проект → Задача → Выполнение → Баллы → Награда**

Дополнительно система позволяет пользователю анализировать результаты своей работы, фиксировать наблюдения после выполнения задач и использовать накопленные данные для последующего анализа с помощью ИИ.

### Основные бизнес-драйверы

#### BD-01 — Ощущение движения к цели

Пользователю необходимо видеть связь между своими долгосрочными целями и конкретными действиями.

Система позволяет пользователю сформировать цепочку:

**Цель → Проект → Задача → Выполнение**

Это позволяет представить выполнение отдельных задач как движение к более крупной цели.

#### BD-02 — Разгрузка памяти пользователя

Пользователь не должен постоянно удерживать в памяти информацию о необходимых действиях и сроках их выполнения.

Система позволяет фиксировать задачи, устанавливать сроки и планировать их выполнение.

#### BD-03 — Поощрение пользователя

Пользователь должен получать дополнительную мотивацию за выполнение задач.

Система предоставляет механизм баллов и наград:

**Выполнение задачи → Получение баллов → Накопление баллов → Получение награды**

Пользователь самостоятельно определяет доступные награды и их стоимость в баллах.

#### BD-04 — Рефлексия и обучение

Пользователь должен иметь возможность анализировать собственный опыт выполнения задач и выявлять факторы, влияющие на результат.

После выполнения задачи система может предложить пользователю вопросы для рефлексии. Пользователь может использовать стандартные вопросы или создавать собственные.

Например, пользователь может зафиксировать наблюдение о том, что после полноценного сна определённый тип задач выполняется легче.

#### BD-05 — Анализ накопленных данных с помощью ИИ

Пользователь должен иметь возможность получать дополнительные выводы из накопленных данных.

ИИ может анализировать задачи, результаты их выполнения и ответы пользователя на вопросы для рефлексии, выявлять закономерности и отвечать на вопросы пользователя на основе разрешённых данных.

# 1.2 Цели качества

Цели качества определяют свойства системы, которые важны помимо непосредственной реализации функциональности.

### QG-01 — Конфиденциальность пользовательских данных

Данные одного пользователя не должны быть доступны другому пользователю без явно предоставленного разрешения.

Особенно важно обеспечить изоляцию данных при работе AI-компонента.

**Приоритет:** критический.

### QG-02 — Полезность AI-анализа

ИИ должен помогать пользователю находить закономерности и делать выводы на основе доступных данных.

Ответы ИИ должны учитывать контекст данных пользователя и поставленный вопрос, а не ограничиваться механическим перечислением сохранённых данных.

**Приоритет:** высокий.

### QG-03 — Целостность игровой экономики

Баллы пользователя должны начисляться и списываться корректно.

Одна задача не должна приводить к повторному начислению баллов из-за повторной обработки одного и того же события. Получение награды не должно приводить к некорректному списанию или созданию отрицательного баланса.

История операций с баллами является источником правды для текущего баланса.

**Приоритет:** критический.

### QG-04 — Сохраняемость истории задач

История выполнения и планирования задач должна сохраняться таким образом, чтобы по ней можно было находить закономерности в работе пользователя.

Изменение текущего состояния задачи не должно приводить к потере следующих фактов:

* **факт выполнения** — когда задача была выполнена и сколько баллов за неё начислено;
* **план против факта** — на какой день задача была запланирована и когда была выполнена фактически;
* **история переносов** — сколько раз и на какие даты задача переносилась.

Именно эти данные являются входом для BD-04 (рефлексия) и FR-13 (AI-анализ). Без них аналитика выполненных задач сводится к подсчёту их количества.

**Приоритет:** высокий.

### QG-05 — Поддерживаемость

Архитектура и кодовая база должны позволять изменять отдельные функциональные области системы без необходимости существенной переработки остальных частей.

Особенно важно обеспечить независимое развитие следующих областей:

* управление задачами;
* управление проектами и целями;
* планирование;
* игровая система баллов и наград;
* рефлексия;
* AI-анализ.

**Приоритет:** высокий.

# 1.3 Заинтересованные стороны

Заинтересованными сторонами системы являются лица, которые используют систему, принимают решения о её развитии или работают с её архитектурой и кодом.

На текущем этапе система является личным проектом, поэтому основные роли выполняются одним человеком. Роли разделены для фиксации различных ожиданий от системы и архитектурной документации.

| Роль                | Заинтересованная сторона             | Ожидания от системы                                                                                                     | Ожидания от архитектурной документации                                                                         |
| ------------------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Владелец продукта   | Автор проекта                        | Система должна решать поставленные продуктовые задачи и развиваться в соответствии с первоначальной концепцией.         | Быстро восстановить бизнес-контекст, цели и основные принципы системы после длительного перерыва в разработке. |
| Пользователь        | Автор проекта                        | Система должна быть удобной, быстрой и помогать поддерживать мотивацию к выполнению задач.                              | Понимать назначение основных функций и логику взаимодействия между ними.                                       |
| Разработчик         | Автор проекта                        | Возможность развивать систему без чрезмерного усложнения существующего кода.                                            | Понимать структуру системы, архитектурные решения, ограничения и причины существующих решений.                 |
| Будущий разработчик | Автор проекта или другой разработчик | Возможность быстро продолжить разработку без необходимости восстанавливать архитектуру исключительно по исходному коду. | Получить необходимый контекст для понимания системы, её бизнес-логики и архитектуры.                           |
