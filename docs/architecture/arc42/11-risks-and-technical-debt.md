# 11. Риски и технический долг

Собрано по ходу написания документации. Каждый пункт — либо непринятое решение, либо расхождение между замыслом и кодом.

## Непринятые решения

| # | Вопрос | Последствие | Где возник |
| - | ------ | ----------- | ---------- |
| R-01 | Могут ли инфраструктурные исключения наследоваться от доменного `AppException`? `DatabaseException` наследуется, правила нет | Иерархия исключений разойдётся по мере роста; неясно, где транслировать ошибки | [8.3](08-crosscutting-concepts.md) |
| R-02 | Критерий «контейнер против ручного `new`» в `Main` | Composition root будет расти хаотично | [8.4](08-crosscutting-concepts.md) |
| R-03 | Какое требование обслуживают `audit_log` и `error_log` | Таблицы существуют без владельца; неясно, что и когда в них писать | [4](04-solution-strategy.md) |
| R-04 | Продуктивное развёртывание: площадка, контейнеризация, бэкапы, управление секретами | Система работает только локально | [7](07-deployment-view.md) |
| R-05 | Типизировать `ErrorResponse.extension` вместо `Map<String, Object>` | Дополнительные данные ошибок без явного контракта | [concepts/ai-assistant/](concepts/ai-assistant/reliability.md) §11 |

## Технический долг

| # | Долг | Риск |
| - | ---- | ---- |
| D-01 | Изоляция данных по `user_id` (QG-01, AR-02) держится на правиле: каждый новый репозиторий фильтрует по `ctx.userId()`. Аутентификация (AR-05) реализована | Репозиторий без фильтра по `user_id` откроет чужие данные |
| D-02 | Схема БД опережает код: таблицы всех предметных областей есть ([database.md](../database.md)), код — только у аутентификации, целей, проектов и задач | Схема может не совпасть с моделью, когда та появится |
| D-05 | `AppException` в `domain` зависит от `org.slf4j.event.Level` | Принятый компромисс ([AD-12](09-architecture-decisions.md)), но формально нарушает независимость домена |

## Риски

| # | Риск | Смягчение |
| - | ---- | --------- |
| RS-01 | Самописная инфраструктура (DI, роутер, транзакции) содержит ошибки, которых нет в зрелых фреймворках | Покрывать тестами; ограничить объём самописного тем, что даёт учебную ценность (LC-03) |
| RS-02 | Учебная цель удлиняет разработку; продуктовая цель важнее учебной ([2.1](02-constraints.md)) | Готовые библиотеки там, где реализация не даёт учебной ценности |
| RS-03 | Передача пользовательских данных во внешний сервис (Gemini). Тариф бесплатный ([AD-20](09-architecture-decisions.md)): провайдер может использовать данные — **принятый риск** | Только данные, явно запрошенные AI из закрытого каталога; без скрытых наград; тексты урезаются; предупреждение в браузере; AI не имеет доступа к БД ([AD-15](09-architecture-decisions.md)) |
| RS-05 | Бесплатная квота Gemini исчерпывается — AI недоступен до сброса | Лимиты на пользователя; предохранитель без лишних вызовов; понятное сообщение пользователю |
| RS-04 | Объём замысла (10 предметных областей) велик для одного разработчика | Реализовывать вертикальными срезами, как сделано с `user` |
