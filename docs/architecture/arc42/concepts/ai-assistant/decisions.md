## 0. Решённые и открытые вопросы

### Решено [Р]

| # | Решение | Следствие для архитектуры |
|---|---------|---------------------------|
| G-1 | **Команд пользователя нет.** Пользователь пишет свободный текст, намерение определяет AI | Один вход `POST /api/ai/requests`. Рамку задают каталог данных, белый список операций, лимиты и согласие пользователя |
| G-2 | AI **создаёт** Goal, Project, Task, Reward | Все четыре типа в контракте `assistant.v1` |
| G-3 | AI **изменяет и удаляет** Goal, Project, Task, Reward — **только с согласием пользователя** на каждую такую операцию. Пользователь видит, **какие** сущности будут изменены или удалены. Нет согласия — операция отменяется | Изменения и удаления исполняются только при явном перечислении в запросе подтверждения ([§6.7](user-flow.md)) |
| G-4 | AI **может** предложить баллы задачи; не предложил — баллы по сложности | `task.points` необязательное |
| G-5 | **Скрытые награды для AI не существуют**: он их не читает, не изменяет, не удаляет и не знает о них | Скрытые награды исключены из каталога целиком, включая счётчики; для них не выдаются дескрипторы ([§6.3](contract.md)) |
| G-6 | Схема БД: нужны таблицы `goals` и `rewards`; в `tasks` нужен `goal_id`; из `projects` убрать `manual_difficulty` | Список изменений схемы — [§6.9](data.md) |
| G-7 | AI **явно запрашивает** данные. Доступны: **задачи, проекты, награды (кроме скрытых), рефлексии, планы, цели** | Каталог запросов ([§6.3](contract.md)) |
| G-8 | AI используется **бесплатно** (бесплатный тариф Gemini), никто не платит; когда квота провайдера исчерпана — ждём сброса | Нет денежного бюджета. Есть обработка исчерпания квоты провайдера и честное распределение квоты между пользователями ([§8](limits-and-security.md)) |
| G-9 | = G-8 | — |
| G-12 | **Согласие на использование данных даётся один раз.** При первом входе на страницу AI-ассистента пользователь видит окно «Чтобы использовать ИИ, вы должны дать согласие на использование ваших данных системы» с кнопками «Согласен» / «Не согласен». Согласие сохраняется на сервере. Без согласия доступа к AI нет — ни во фронтенде, ни на сервере. Каждый раз подтверждать, какие данные AI читает, не нужно. Статистика — вычисляемые данные на основе задач и проектов | Таблица `ai_consents`; сервер проверяет согласие **до** любого вызова AI, иначе → `403 AI_CONSENT_REQUIRED` ([§6.10](user-flow.md)). Отдельного источника «статистика» в каталоге нет |
| G-13 | Баллы задачи: **максимум 1000** (для ручного ввода и для AI) | Диапазон `points` 1..1000 (минимум 1 — [П]) |
| G-14 | Задача может существовать **без проекта и без цели** | Одиночные задачи в плане разрешены |
| G-15 | При удалении цели её проекты и задачи **отвязываются**, а не удаляются (как при удалении проекта [Ф V3]) | `goal_id … ON DELETE SET NULL` |
| G-16 | AI **не выполняет и не отменяет** задачи — это только вручную | Статуса нет в белом списке изменяемых полей; просьба «выполни задачу» → `REFUSED` |
| G-17 | Выполненные задачи **можно изменять и удалять** (и вручную, и через AI с согласием) | Уже начисленные баллы не меняются [П, следствие AD-16]: баланс считается по истории операций, при удалении задачи запись истории остаётся [Ф V7: `task_id ON DELETE SET NULL`]. |
| G-18 | Пароль скрытых наград **один на пользователя** и общий для всех его скрытых наград | Хеш пароля хранится у пользователя, а не у награды ([§6.9](data.md)) |
| G-11 | **Правила дат:** срок задачи не позже срока её проекта; срок проекта не раньше сроков его задач; дату начала можно ставить в прошлом | Доменные правила, общие для ручного API и AI. Проверяются на **итоговом** состоянии после всех операций плана ([§8](limits-and-security.md)) |
| G-20 | При удалении выполненной задачи **факты выполнения сохраняются** и продолжают учитываться в аналитике | Append-only записи о выполнении не удаляются, ссылка на задачу обнуляется (QG-04) |
| G-21 | AI может и **отвечать** (например, сделать анализ), и **выполнять операции** — в том числе в одном сообщении. Если операции были, пользователь **всегда получает отчёт**: какие сущности созданы, изменены, удалены. **Без деталей** («было → стало» не показывается). Фронтенд показывает отчёт отдельным блоком в сообщении AI со ссылками на сущности | `answer` разрешён и в `PROPOSAL`. Отчёт — список (тип, ID, название, результат), построенный из фактического результата, а не из текста AI ([§6.7](user-flow.md)) |
| G-10 | **Карточка подтверждения в чате** — часть страницы AI-ассистента. Сообщение AI с изменениями или удалениями содержит карточку со списком затронутых сущностей (тип + название) и галочками; кнопки «Выполнить отмеченное» / «Отклонить». После выполнения — отчёт | Требование к фронтенду; данные карточки — [§6.6](user-flow.md) |
| G-23 | **Срок можно ставить в прошлом** (как и дату начала) | Ограничения «не в прошлом» нет ни для ручного ввода, ни для AI |
| G-24 | **Отзыв согласия и версия текста соглашения пока не нужны.** Согласие даётся один раз и действует бессрочно | Нет `DELETE /api/ai/consent`, нет версии текста. Если понадобится — отдельное решение |
| G-25 | **Создание выполняется без подтверждения пользователя.** Подтверждение нужно только для изменений и удалений | Создания исполняются сразу в фазе 1, после проверки ответа AI; пользователь получает отчёт. Если есть изменения или удаления, они ждут подтверждения ([§6.7](user-flow.md)) |
| G-19 | **Без авторизации системой пользоваться нельзя** | Любой AI-endpoint без действующей сессии → `401`; фильтр аутентификации (D-01) — обязательное предусловие |

### Открыто

Открытых продуктовых вопросов нет. Технический вопрос — в конце документа.

**Предусловия реализации:**
- `rest/filters` (D-01): без авторизации системой пользоваться нельзя [Р G-19];
- ручные сценарии создания, изменения, удаления и чтения всех четырёх сущностей: AI-путь их переиспользует;
- изменения схемы из [§6.9](data.md).

## 16. Alternatives and trade-offs

| # | Решение | Альтернатива | Почему выбрано | Цена |
|---|---------|--------------|----------------|------|
| 1 | Явный `DATA_REQUEST` в собственном контракте [Р G-7] | Сервер собирает контекст заранее; native function calling как основа | Без команд сервер не знает, что нужно; собственный исход одинаков для всех провайдеров | +1–2 вызова, расход бесплатной квоты |
| 2 | Закрытый каталог | Свободные фильтры | Проверяется перечислением | Новые данные — изменение кода |
| 3 | Дескрипторы с версией | Реальные ID | Нет IDOR и утечки ID; обнаружение устаревших данных | Реестр на запрос |
| 4 | Создания — сразу, без подтверждения [Р G-25]; изменения и удаления — только явным перечислением [Р G-3] | Подтверждать всё, включая создания | Создание ничего не портит; меньше кликов | Ошибочно созданное (до 40 сущностей) пользователь удаляет сам; единственная защита от «наплодить мусора» — лимиты |
| 5 | Карточка и отчёт — список сущностей без деталей [Р G-21] | Показ «было → стало» и последствий удаления | Решение владельца продукта: проще интерфейс и реализация | Пользователь подтверждает изменение, не видя, что именно изменится (видит только пояснение AI); при удалении не видит, сколько задач останется без проекта |
| 6 | `409` при изменении цели после предпросмотра | Применить поверх (last write wins) | Согласие было на конкретное состояние | Иногда нужен повторный запрос |
| 7 | Дерево для создания + `ref` только для «перенести в новое» | `ref` везде | Меньше классов ошибок | Нет «многие ко многим» |
| 8 | Отказ при превышении лимита | Обрезка | Обрезка молча меняет смысл | Лишний запрос |
| 9 | Всё или ничего | Частичный успех | Единица согласия = единица атомарности | Одна ошибка отменяет пакет |
| 10 | Бесплатный тариф + предохранитель [Р G-8] | Платный тариф | Решение владельца | Данные могут использоваться провайдером; недоступность при исчерпании квоты |
| 11 | JDK `HttpClient` | SDK Google GenAI | Нет привязки; LC-03 | Формат вручную |
| 12 | Синхронная фаза 1 | 202 + опрос | Проще; виртуальные потоки | Ожидание до 90 с |
| 13 | Нет истории диалога | Чат с памятью | Меньше хранимых данных | Уточнения менее удобны |
