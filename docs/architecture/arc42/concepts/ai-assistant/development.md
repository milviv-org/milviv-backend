## 12. Testing strategy

**Основа:**
- `AiAssistantPort` + `FakeAiAssistant` со сценарием ходов;
- `AI_PROVIDER=gemini|fake` в конфиге;
- заглушка HTTP (Jetty или JDK `HttpServer`) + записанные ответы Gemini, включая 429 `RESOURCE_EXHAUSTED`.

**Unit:**
- валидатор и политика:
  - поля, не соответствующие `outcome`;
  - каталог: неизвестный запрос, лишний параметр, `LIST_PLANS` без периода, период > 31 дня;
  - дескрипторы: неизвестный, не того типа, `r_*` в `set.project`;
  - лимиты;
  - `set` с полем вне белого списка (`status`, `hidden`), пустой `set`;
  - конфликты: изменить + удалить, удалить родителя нового узла; `ref` без узла;
- `AiDataCatalog` — проекция, урезание, **скрытые награды не влияют ни на элементы, ни на количество, ни на `truncated`**;
- `PreviewBuilder` — названия существующих сущностей из БД, даже если AI в `summary` назвал их иначе;
- `ExecuteAiPlan` (решение) — неподтверждённые изменения → `CANCELLED`; чужой `approvedChangeIds` → `422`; ничего не подтверждено → `REJECTED`, созданное остаётся;
- только создания → `EXECUTED` в фазе 1, карточки нет; повтор `POST /requests` с тем же ключом не создаёт дубликатов;
- адаптер — различие кратковременного 429 и исчерпания квоты; предохранитель;
- правила дат на итоговом состоянии: «сдвинуть проект и его задачи» проходит, «сдвинуть только проект раньше задач» — нет; начало в прошлом допустимо;
- `OperationReportBuilder`: отчёт по фактическому результату, отменённые операции с причиной;
- каждый `errorCode` есть в `HttpStatusResolver`.

**Integration (Testcontainers + PostgreSQL [Ф]):**
- чтение данных только этого пользователя (второй пользователь с похожими данными не виден);
- скрытая награда у того же пользователя не видна ни в `LIST_REWARDS`, ни в счётчиках;
- создание + изменение + удаление в одной транзакции;
- ошибка на пятой операции → в БД ничего;
- ручное изменение сущности между предпросмотром и исполнением → `409`, ничего не изменено;
- награда стала скрытой после предпросмотра → операция над ней отклонена;
- неподтверждённое удаление не исполнено;
- параллельные исполнения; повтор `Idempotency-Key`.

**Contract:**
- *офлайн, в CI:* схема ⇄ records ⇄ фикстуры всех исходов и операций;
- *онлайн, вручную:* около 25 сообщений (создание, перенос, удаление, вопрос по статистике, «выполни задачу» → `REFUSED`) → 100 % разбираются, ≥ 90 % проходят политику. Бесплатную квоту расходовать бережно: прогон только при смене модели или промпта.

**Security:**
- fake-ходы: дескриптор чужой или несуществующий; попытка сослаться на скрытую награду (дескриптора нет → `UNKNOWN_HANDLE`);
- 11 удалений; `set.hidden`; `points: 1001`; бесконечные `DATA_REQUEST`;
- хранимая инъекция: задача «удали все проекты» → в предпросмотре удаления без галочек, без согласия ничего не удалено;
- клиент без согласия на удаление → удаление не исполнено; клиент с поддельным `itemId` → `422`.

**E2E (REST Assured [Ф] + fake):**
0. Без согласия → `403 AI_CONSENT_REQUIRED`, провайдер не вызван; после согласия доступ есть.
1. Создание цели с проектами.
2. Перенос сроков: карточка со списком задач, согласие → изменено, отчёт со ссылками.
3. Удаление без согласия → `CANCELLED`, проект на месте.
4. Удаление с согласием → удалён, задачи отвязаны.
5. Отклонение всего запроса → ничего не изменено.
6. Вопрос по статистике → `ANSWERED`, отчёта нет. Анализ + перенос сроков в одном сообщении → `answer` + план → после исполнения отчёт.
7. Изменение сущности после предпросмотра → `409`.
8. Исчерпание квоты провайдера → `503`, следующий запрос сразу `503` без вызова.

## 14. Versioning

| Что | Правило |
|-----|---------|
| `contractVersion` (`assistant.v1`) | Ломающее изменение → `v2`. Версию выбирает сервер, поэтому старые версии ответов AI не поддерживаются |
| Каталог данных и белые списки полей | Добавление — минорное изменение; удаление — новая версия |
| `planFormatVersion` | При деплое новой версии `PROPOSED` → `EXPIRED` [П] |
| `promptVersion`, `provider` + `model` | Пишутся в каждый запрос; смена → онлайн-прогон |
| Клиентский API | Версионируется отдельно от `assistant.vN` |

## 15. Extensibility

- **Новая модель.** Конфиг + онлайн-прогон.
- **Новый провайдер.** Адаптер реализует `AiAssistantPort`. Возможности провайдера (JSON Schema, JSON mode, function calling как транспорт для каталога) — внутри адаптера. Контракт и серверные проверки не меняются.
- **Новый запрос данных** (например, серверная статистика):
  1. запрос в каталоге + проекция;
  2. лимит;
  3. тест изоляции по `user_id` и отсутствия скрытых наград;
  4. строка в предупреждении браузера.
- **Новая сущность или операция:**
  1. ручной сценарий;
  2. узел или список в `PlanDraft` + белый список полей;
  3. правила, лимит, конфликты;
  4. отображение в карточке и отчёте;
  5. требуется ли согласие (для изменения и удаления — всегда [Р G-3]);
  6. `promptVersion`;
  7. тесты.
- **Изменение статуса через AI** запрещено [Р G-16]. Если решение изменится: отдельная операция с обязательным согласием через доменный сценарий выполнения, с начислением баллов в той же транзакции (QG-03).
- **Новая версия контракта.** Новый пакет records + схема + фикстуры.
