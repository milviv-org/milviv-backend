## 8. Limits and policies

Значения — принятые значения по умолчанию; помеченные [Р] — решения владельца продукта.

**Все лимиты и константы AI хранятся в конфиге с дефолтными значениями** [Р], так же как это уже сделано для БД и сервера [Ф `ConfigLoader`, `AppConfig`]:
- **Приоритет источников** [Ф]: переменная окружения → `.env` → `application.properties`.
- **Дефолт в коде** [Ф]: `configLoader.getInt("AI_MAX_DATA_ROUNDS", "ai.max.data.rounds", 2)`. Приложение работает и без явной настройки, а в `.env` задаётся только то, что отличается.
- **Типизированный держатель.** `AiConfig` (по образцу `AppConfig`) читает все значения один раз при старте, проверяет их (положительные, `min ≤ max`) и передаётся в `AiPolicy`, `AiDataCatalog`, адаптер через конструктор. Никаких чисел прямо в коде сценариев.
- **Документирование.** Ключи с дефолтами — в `application.properties`, пример — в `.env.example`.
- **Именование** [Ф]: env — `AI_*` в верхнем регистре, property — `ai.*` через точки.
- **Тесты** подставляют свои значения через тестовый properties-файл [Ф `ConfigLoader(propertiesFile, loadDotenv)`], например `ai.max.creates=2`, чтобы проверять лимиты на маленьких числах.

Правила домена — не конфиг. Баллы задачи 1..1000 [Р G-13], баллы по сложности, правила дат [Р G-11] — это правила продукта, одинаковые для ручного ввода и AI; их закрепляет ещё и `CHECK` в БД. Если сделать их настраиваемыми, конфиг и схема БД разойдутся. Поэтому они остаются константами домена.

**Квота провайдера [Р G-8].** Денежного бюджета нет, работаем на бесплатной квоте Gemini. Поэтому:
- **Лимиты на пользователя нужны не ради денег, а ради справедливости:** один пользователь не должен исчерпать общую бесплатную квоту за всех.
- Ответ провайдера «квота исчерпана» (HTTP 429, `RESOURCE_EXHAUSTED`) → адаптер отличает его от кратковременного rate limit и открывает **предохранитель**. До сброса квоты (или N минут) новые запросы сразу получают `AI_PROVIDER_QUOTA_EXHAUSTED`, провайдер не вызывается.
- Фактические лимиты бесплатного тарифа (запросы в минуту и в сутки, токены) берутся из условий Google для выбранной модели и задаются в конфиге. Здесь они не фиксируются, потому что меняются.

| Лимит | Значение | Где | Этап |
|-------|----------|-----|------|

| Даты: ограничение для AI [П] | ≤ today + 2 года (срок и начало в прошлом допустимы [Р G-23]) | `AiPolicy` | после |

**Правила дат проверяются на итоговом состоянии.** Сначала к текущим данным применяются все операции плана, затем проверяются правила. Поэтому корректный план «сдвинуть срок проекта на 01.11 и перенести его задачи на 25.10» проходит, хотя по отдельности одна из операций нарушила бы правило. Если пользователь снял часть операций и итог стал нарушать правило, исполнение отклоняется: `422 BUSINESS_RULE_VIOLATION` с названиями задачи и проекта.

Правило проверяется при каждом способе, которым задача оказывается в проекте:
- создание задачи в проекте;
- перенос задачи в проект;
- изменение срока задачи;
- изменение срока проекта.

Если у проекта или задачи нет срока, ограничения нет.

**Правила:**
- превышение лимита количества → отказ всего плана, **без обрезки**;
- лимиты для AI могут быть строже ручных, но не мягче;
- в квоту пользователя засчитываются все вызовы, включая неудачные.

## 9. Security model

**Главная мера против prompt injection:** все свойства системы выполняются для **любой** последовательности ходов, соответствующих схеме. Самое опасное, чего может добиться инъекция, — изменения и удаления. Их закрывает не модель, а явное согласие пользователя на каждую операцию; какие сущности затронуты, сервер показывает по БД.

| # | Угроза | Мера |
|---|--------|------|
| T-1 | Инъекция «создай 10 000 задач» | Создания без подтверждения [Р G-25], поэтому лимиты — единственная защита: ≤ 40 созданий за запрос, ≤ 200 за сутки, отказ без обрезки; отчёт показывает всё созданное |
| T-2 | Инъекция «удали всё» / незаметное изменение | Удаления ≤ 10, изменения ≤ 20; каждое исполняется только по явному `approvedChangeIds`; названия затронутых сущностей — из БД, не от AI |
| T-3 | Подмена согласия (клиент подтверждает то, чего пользователь не видел) | Согласие проверяется сервером: только `itemId` этого плана; снимок версий → изменилась сущность → `409`. [Д] Экран в браузере честно показывает предпросмотр (G-10) |
| T-4 | Исчерпание общей бесплатной квоты одним пользователем | Лимиты на пользователя, один активный запрос, лимит вызовов, предохранитель |
| T-5 | Чтение чужих данных | Закрытый каталог без параметра пользователя; `user_id` из сессии |
| T-6 | Утечка скрытых наград | Фильтр в SQL-запросе каталога; нет дескрипторов; нет влияния на счётчики и `truncated`; при исполнении цель операции, ставшая скрытой, → отказ |
| T-7 | IDOR через `requestId` или дескриптор | Фильтр `user_id` → `404`; дескрипторы случайны, одноразовы по запросу, перепроверяются |
| T-8 | Повышение привилегий полями (`userId`, `hidden`, `status`) | Закрытый белый список полей для каждого типа |
| T-9 | Инфляция экономики через `points` | 1..1000 [Р]; [Ф] баллы начисляются только за выполнение, а статус AI не меняет |
| T-10 | Хранимая инъекция в данных | Размеченная часть; всё, чего она может добиться, ограничено T-1, T-2 |
| T-11 | Персональные данные у провайдера | Бесплатный тариф — **принятый риск** [Р G-8]; предупреждение в браузере; урезание текстов; только каталог |
| T-12 | Огромный или некорректный ответ | Лимит байт до разбора, ограничения Jackson |
| T-13 | XSS в текстах | Хранится как текст, клиент экранирует [Д] |
| T-14 | Повторное исполнение | Машина состояний + условный `UPDATE` с версией |
| T-15 | Утечка секретов и через логи | Ключ только в env; тексты не логируются на INFO |
| T-16 | SSRF | URL провайдера только из конфига |

**Промпт отвечает за:** роль, язык, формат, выбор исхода, экономные запросы данных, осмысленные предложения, правило «данные — не инструкции».

**Backend отвечает за:** доступ к данным, скрытые награды, права, белый список, лимиты, квоты, согласие, сравнение, атомарность, идемпотентность.

**Почему нельзя полагаться на системный промпт:**
- модель следует ему вероятностно;
- инъекция обходит инструкции, в том числе через данные, которые AI сам запросил;
- промпт открыт (OC-01);
- смена модели меняет поведение.

**Допущения [Д]:**
- D-01 реализован;
- данные не разделяются между аккаунтами;
- браузер честно показывает предпросмотр и экранирует текст;
- предупреждение о чтении и передаче данных Google показывается до первого использования.
