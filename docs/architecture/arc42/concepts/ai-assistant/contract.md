# AI Assistant — Контракт сервер ⇄ AI

[← AI Assistant](README.md) · Метки [Ф] [Р] [П] [Т] [TO] [Д] — см. [README](README.md).

Что сервер передаёт AI и что AI может ответить.

---

## 6. AI contract

Два контракта, их нельзя смешивать:
- **Server ⇄ AI** (`assistant.v1`) — внутренний;
- **Client ⇄ Server** (`/api/ai/...`) — публичный.

Диалог внутри одного запроса — последовательность ходов; ход AI — объект `AiTurn`.

---

### 6.1 Server → AI: первый ход

```json
{
  "contractVersion": "assistant.v1",
  "promptVersion": "assistant@1",
  "locale": "ru-RU", "today": "2026-09-27", "timezone": "Asia/Almaty",
  "userMessage": "Хочу выучить английский",
  "round": 1, "maxDataRounds": 2,
  "limits": { "maxCreates": 40, "maxUpdates": 20, "maxDeletes": 10,
              "titleMaxLength": 100, "descriptionMaxLength": 1000, "taskPointsMax": 1000 },
  "catalog": {
    "difficulty": [ { "value": "NOVICE", "points": 2 }, { "value": "APPRENTICE", "points": 3 },
                    { "value": "ADEPT", "points": 5 }, { "value": "EXPERT", "points": 8 },
                    { "value": "MASTER", "points": 10 }, { "value": "LEGENDARY", "points": 20 } ],
    "dataQueries": [ "LIST_GOALS", "LIST_PROJECTS", "LIST_TASKS", "LIST_REWARDS", "LIST_PLANS", "LIST_REFLECTIONS" ],
    "operations": [ "CREATE", "UPDATE", "DELETE" ]
  }
}
```

| Поле | Назначение |
|------|------------|
| `contractVersion`, `promptVersion` | Форма ответа; шаблон инструкций (в аудит) |
| `locale`, `today`, `timezone` | Корректные даты |
| `userMessage` | Недоверенный текст, в отдельной размеченной части |
| `round`, `maxDataRounds` | Сколько раундов данных осталось; соблюдение проверяет сервер |
| `limits`, `catalog` | Подсказки модели; сложности — из доменного enum [Ф] |

**Не передаётся никогда:** служебные ID, `userId`, реальные ID, email и имя, баланс, **скрытые награды и сам факт их существования**, данные других пользователей.

### 6.2 AI → Server: `AiTurn v1`

| Поле | Когда | Назначение |
|------|-------|------------|
| `contractVersion` | всегда | const `"assistant.v1"` |
| `outcome` | всегда | `DATA_REQUEST \| PROPOSAL \| ANSWER \| CLARIFICATION_NEEDED \| REFUSED` |
| `dataRequests[]` (1..3), `dataRequestReason` (≤ 200) | `DATA_REQUEST` | Явный запрос данных; причина показывается пользователю |
| `summary` (≤ 500), `plan` | `PROPOSAL` | Пояснение и черновик (§6.5) |
| `answer` (≤ 2000) | `PROPOSAL`, необязателен | Текст рядом с операциями — например, результат анализа, на основе которого AI предлагает изменения [Р G-21] |
| `answer` (≤ 2000) | `ANSWER` | Текстовый ответ (например, анализ); ничего не исполняется |
| `clarificationQuestion` (≤ 300) | `CLARIFICATION_NEEDED` | Вопрос пользователю |
| `refusalReason` | `REFUSED` | `OFF_TOPIC \| UNSUPPORTED_OPERATION \| OTHER` (например, «выполни задачу», G-16) |

**Правила разбора:**
- поле, не соответствующее `outcome`, → отказ;
- неизвестное поле → отказ;
- дубликат ключа → отказ;
- мягкая нормализация одна: обрезка пробелов и удаление управляющих символов, кроме `\n`.

**Типизация [П]:** records; sealed-иерархии для `outcome`, `DataQuery` и узлов плана; `assistant.v1.schema.json` сверяется с records контрактным тестом.

### 6.3 Явный запрос данных: каталог [Р G-7, G-12]

**Пример запроса AI:**

```json
{ "outcome": "DATA_REQUEST", "dataRequestReason": "Найти задачи по грамматике",
  "dataRequests": [ { "query": "LIST_TASKS", "project": "p_2mZa", "goal": null, "status": "ACTIVE", "period": null } ] }
```

**Каталог v1.** Параметры типизированы; параметр, не предусмотренный для запроса, должен быть `null`.

| `query` | Параметры | Возвращает (проекция) | Дескрипторы |
|---------|-----------|------------------------|-------------|
| `LIST_GOALS` | — | название, описание | `g_*` |
| `LIST_PROJECTS` | `goal?`, `status?` | название, описание, статус, срок, цель | `p_*` |
| `LIST_TASKS` | `project?`, `goal?`, `unassigned?`, `status?`, `period?` | название, описание, статус, сложность, баллы, начало, срок, дата выполнения, проект, цель | `t_*` |
| `LIST_REWARDS` | — | название, описание, стоимость — **только нескрытые** | `r_*` |
| `LIST_PLANS` | `period` (обязателен, ≤ 31 дня) | дата или дни недели повторения, время, название, задача | нет (только чтение) |
| `LIST_REFLECTIONS` | `task?`, `period?` | задача, дата выполнения, вопрос, ответ | нет (только чтение) |

**Правила:**
- Каждый запрос исполняется с `user_id` из сессии через те же репозитории, что и ручной API [Ф AD-14].
- Чтение этих категорий разрешено согласием на использование данных, которое пользователь дал один раз [Р G-12, [§6.10](user-flow.md)]. Отдельно подтверждать каждое чтение не нужно. Текст соглашения сообщает, **что** читается и что данные уходят Google.
- **Скрытые награды** отфильтровываются в запросе к БД, а не после выборки. Они не влияют ни на `truncated`, ни на количество, ни на ошибки. Для AI их нет (G-5).
- **Статистика** [Р G-12] — не отдельный запрос. AI вычисляет её из `LIST_TASKS` и `LIST_PROJECTS`. Если объёмов не хватит, можно добавить серверный агрегирующий запрос [П].
- **Размер:**
  - ≤ 100 элементов на запрос (пометка `truncated`);
  - описания и ответы рефлексии урезаются до 1000 символов;
  - ≤ 3 запроса за раунд, ≤ 2 раунда.
- Дескриптор выдаётся для каждой возвращённой цели, проекта, задачи и нескрытой награды. Запоминается **версия** сущности на момент чтения.
- **Журнал прочитанного** (тип запроса и количество, без содержимого) хранится в `AiRequest` и показывается пользователю.

**Ответ сервера AI** (следующий ход, размечен как данные):

```json
{ "round": 2,
  "dataResults": [ { "query": "LIST_TASKS", "truncated": false,
    "items": [ { "handle": "t_9fLm", "title": "Времена группы Simple", "status": "ACTIVE",
                 "difficulty": "APPRENTICE", "points": 3, "startDate": null, "deadline": "2026-10-01",
                 "completedAt": null, "project": "p_2mZa", "goal": null } ] } ],
  "rejectedRequests": [] }
```

Запрос, отклонённый политикой, попадает в `rejectedRequests` с кодом, а остальные исполняются [П]. Весь ход отвергается только при нарушении контракта. Исчерпав раунды, модель обязана вернуть не `DATA_REQUEST`.

### 6.4 Дескрипторы

- Формат: префикс типа + случайная строка (`g_k7Qx`, `p_2mZa`, `t_9fLm`, `r_Q3aa`). Не производная от ID.
- Действуют в рамках одного `AiRequest`. `HandleRegistry` хранит дескриптор → (тип, ID, версия при чтении).
- В плане AI ссылается только на выданные ему дескрипторы; тип определяется префиксом и должен подходить к месту ссылки.
- **Подмена ID (IDOR) невозможна:** дескрипторы выдаются только после выборки с `user_id`.
- При исполнении каждая сущность проверяется снова: существует, принадлежит пользователю, **версия не изменилась**, награда не стала скрытой.

### 6.5 План: `PlanDraft v1`

План состоит из трёх частей:
- **создание** — дерево;
- **изменения** — списки по типам сущностей;
- **удаления** — список дескрипторов.

```json
{
  "outcome": "PROPOSAL",
  "summary": "Новый проект «Чтение»; задачи по грамматике перенесены на неделю; удалён пустой проект «Старый».",
  "plan": {
    "create": {
      "goal": null,
      "projects": [
        { "ref": "n_read", "existing": null, "title": "Чтение", "description": null, "deadline": "2026-12-01",
          "tasks": [ { "title": "Прочитать адаптированную книгу", "description": null,
                       "difficulty": "EXPERT", "points": 12, "startDate": null, "deadline": "2026-11-15" } ] }
      ],
      "tasks": [],
      "rewards": []
    },
    "update": {
      "tasks": [ { "target": "t_9fLm",
                   "set": { "deadline": { "value": "2026-10-08" }, "title": null, "description": null,
                            "difficulty": null, "points": null, "startDate": null, "project": null, "goal": null } } ],
      "projects": [], "goals": [], "rewards": []
    },
    "delete": [ { "target": "p_Old1" } ]
  }
}
```

**Создание** — дерево, как раньше:

| Узел | Поля | Правила |
|------|------|---------|
| `create.goal` | `GoalNode \| null` (≤ 1) | `existing` = `g_*` → добавить детей в существующую цель, `title`/`description` = `null`; иначе новая цель, `title` обязателен |
| `GoalNode.projects[]`, `.tasks[]` | ≤ 10 / ≤ 10 | Проекты и задачи цели |
| `ProjectNode` | `ref?`, `existing?`, `title`, `description`, `deadline`, `tasks[]` (≤ 10) | `existing` = `p_*` → добавить задачи в существующий проект |
| `create.projects[]` | проекты без цели | — |
| `create.tasks[]` | одиночные задачи [Р G-14] | — |
| `task` | `title`, `description`, `difficulty` (обязателен), `points` (1..1000 \| null [Р G-4, G-13]), `startDate`, `deadline` | `points = null` → по сложности |
| `create.rewards[]` | `title`, `description`, `cost` (1..100 000) | Скрытость не задаётся (G-5) |
| `ref` | `^n_[a-z0-9]{1,8}$`, необязателен | Имя **нового** узла; нужно только затем, чтобы изменения могли перенести в него существующие задачи или проекты. Проверяется уникальность, существование и тип |

**Изменение.** Отдельный список для каждого типа, `set` — типизированный объект. `null` = поле не меняется, `{ "value": x }` = установить `x` (в том числе `{ "value": null }` = очистить).

| Тип | Изменяемые поля (белый список) | Не изменяется через AI |
|-----|--------------------------------|-------------------------|
| задача `t_*` | `title`, `description`, `difficulty`, `points`, `startDate`, `deadline`, `project` (`p_*` / `n_*` / очистить), `goal` (`g_*` / очистить) | статус, дата выполнения, владелец (G-16) |
| проект `p_*` | `title`, `description`, `deadline`, `goal` (`g_*` / очистить) | статус, сложность (её вычисляет система [Ф]) |
| цель `g_*` | `title`, `description` | — |
| награда `r_*` | `title`, `description`, `cost` | `hidden`, пароль, обмен баллов (G-5) |

**Удаление:** `delete[] = [{ "target": "<дескриптор g_/p_/t_/r_>" }]`.

**Проверки конфликтов (отказ всего плана):**
- одна цель в двух операциях (изменить и удалить; изменить дважды);
- новый узел или изменение ссылается на удаляемую сущность;
- пустой `set`;
- `set.project` и `set.goal` противоречат доменному правилу связи (если оно будет задано).

**Почему дерево для создания, а не временные `ref` везде [П]:** висячие ссылки и циклы среди новых сущностей невозможны по построению. `ref` оставлен только для одного случая — «перенести существующее в новое». Его проверки просты: ровно один узел с этим `ref`, подходящий тип.
