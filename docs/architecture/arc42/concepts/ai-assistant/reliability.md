## 10. Transactions and idempotency

### 10.1 Атомарность: всё или ничего [П]

- **Две транзакции, каждая — всё или ничего** [Ф AD-08]:
  - создания — одна транзакция в фазе 1;
  - подтверждённые изменения и удаления — одна транзакция в фазе 2.
  
  Отказ от изменений не откатывает уже созданное: это разные решения (создание не требует согласия, G-25).
- **Порядок исполнения:**
  1. фаза 1: создания (цель → проекты → задачи → награды);
  2. фаза 2: изменения (могут ссылаться на созданные в фазе 1 `n_*`), затем удаления.
- **Ошибка на любом шаге** → откат этой транзакции. В фазе 1 ничего не создано, запрос `FAILED`. В фазе 2 ничего не изменено, статус остаётся `PROPOSED`. Временная ошибка → повтор через `RetryableTransactionManager` [Ф].
- **Устаревший предпросмотр.** Для каждой цели изменения или удаления сравнивается версия со снимком. Не совпала → `409 TARGET_CHANGED`, откат. Пользователь соглашался изменить сущность в том состоянии, в каком она была при предложении; после стороннего изменения это уже другое решение.
- **Много независимых операций.** Частичного применения нет. Большой объём делится на несколько запросов; единица атомарности = единица подтверждения.

### 10.2 Идемпотентность

| Идентификатор | Кто создаёт | Зачем |
|---------------|-------------|-------|
| `X-Request-Id` | сервер | Корреляция логов, не дедупликация [Ф `error_log.request_id`] |
| `Idempotency-Key` | клиент, на `POST /requests` | Повтор после таймаута не вызывает AI снова. UNIQUE(`user_id`, ключ) + хеш тела |
| `requestId` | сервер | Естественный ключ идемпотентности исполнения и отклонения |
| `itemId` | сервер | Адресация операций, согласие, результат |
| дескриптор + версия | сервер | Ссылка на существующую сущность и защита от устаревших данных |

**Сценарии:**
- **`Idempotency-Key` теперь критичен:** `POST /requests` сам создаёт сущности, и без ключа повтор после таймаута создал бы их второй раз.
- **Повтор `POST /requests`:**
  - завершён → сохранённый результат;
  - `PENDING_AI` → `409`;
  - другое тело → `422`.
- **Таймаут при исполнении.** Транзакция либо закоммитилась, либо откатилась; повтор даёт тот же итог без дубликатов.
- **Два параллельных исполнения.** Условный `UPDATE … WHERE status='PROPOSED' AND version=?` пропускает ровно одно.
- **Исполнение после отклонения** (и наоборот) → `409 REQUEST_STATE_CONFLICT`.
- **Ретраи к провайдеру** безопасны: до исполнения ничего не пишется.
- **Сервер упал во время цикла.** `PENDING_AI` старше таймаута считается `FAILED` при следующем обращении.

## 11. Error model

**Внутри:**
- адаптер возвращает sealed `AiFailure`: `ProviderUnavailable`, `ProviderRateLimited`, `ProviderQuotaExhausted`, `Timeout`, `OutputTruncated`, `Malformed`, `ProviderRefused`;
- валидатор возвращает `List<Violation(code, path, limit)>`.

**Наружу:** наследники `AppException` [Ф 8.3]; новые коды добавляются в `HttpStatusResolver`.

| errorCode | HTTP | Повторять? | Пользователь видит |
|-----------|------|------------|--------------------|
| `VALIDATION` | 400 | нет | Поля ввода |
| `NOT_FOUND` | 404 | нет | «Не найдено» (в том числе чужое) |
| `AI_CONSENT_REQUIRED` | 403 | после согласия | «Чтобы использовать ИИ, дайте согласие на использование ваших данных» |
| `AI_QUOTA_EXCEEDED` | 429 | позже | «Ваш лимит запросов к AI на сегодня исчерпан», `retryAfterSeconds` |
| `AI_PROVIDER_QUOTA_EXHAUSTED` | 503 | позже | «Бесплатный лимит AI исчерпан, попробуйте позже» |
| `AI_REQUEST_IN_PROGRESS` | 409 | позже | «Предыдущий запрос ещё обрабатывается» |
| `IDEMPOTENCY_KEY_REUSED` | 422 | нет | Ошибка клиента |
| `AI_PROVIDER_UNAVAILABLE` | 503 | да | «AI временно недоступен» |
| `AI_TIMEOUT` | 504 | да | «AI не ответил вовремя» |
| `AI_INVALID_RESPONSE` | 502 | да | «Не удалось обработать запрос, попробуйте переформулировать» |
| `AI_PLAN_TOO_LARGE` | 422 | сузив запрос | «Слишком много изменений за раз — уточните запрос» |
| `AI_REFUSED` | 422 | нет | По причине: «Не относится к целям и задачам» / «Эта операция недоступна для AI» |
| `PLAN_EXPIRED` | 410 | нет | «Предложение устарело» |
| `TARGET_CHANGED` | 409 | новый запрос | «„…“ изменилась после предложения. Ничего не изменено — отправьте запрос заново» |
| `APPROVAL_INVALID` | 422 | нет | Ошибка клиента (подтверждён несуществующий или не тот элемент) |
| `REQUEST_STATE_CONFLICT` | 409 | нет | «Запрос уже исполнен или отклонён» |
| `BUSINESS_RULE_VIOLATION` | 422 | нет | Причина, например «Срок задачи „X“ позже срока проекта „Y“» |
| (прочее) | 500 | да | «Внутренняя ошибка. Ничего не изменено» + ID корреляции |

**Правила:**
- наружу не уходят: текст ошибки провайдера, сырой ответ AI, промпт, stack trace [Ф AD-11];
- ошибки исполнения всегда означают «ничего не изменено»;
- `TARGET_CHANGED` называет сущность по названию, но **никогда не упоминает скрытые награды**: они не могут быть целью операции;
- дополнительные данные ошибки — типизированные records. [Ф] Сейчас `ErrorResponse.extension` — `Map<String, Object>`; открытый вопрос.
