## 8.1 Транзакции и конкурентность

**Проблема.** Одно действие меняет несколько таблиц и должно быть атомарным (QG-03), при этом данные могут меняться конкурентно (AR-01).

**Решение.** `TransactionManager` (интерфейс в `application`, реализация в `infrastructure`) с явным вызовом `execute(...)`. Соединение передаётся неявно через `ConnectionHolder` (ThreadLocal). Конкурентность — оптимистичные блокировки (`VersionedAggregate` → `OptimisticLockException`) плюс декоратор `RetryableTransactionManager` с backoff + jitter.

**Правила:**

* граница транзакции — прикладной сценарий, не репозиторий и не контроллер;
* внешние вызовы (Gemini) — строго вне транзакции;
* `incrementVersion()` вызывает только репозиторий после успешного `UPDATE`;
* транзакция объявляется явным вызовом, не аннотацией (LC-03 — без «магии»);
* `SERIALIZABLE` — только там, где критична гонка; по умолчанию `READ_COMMITTED`.

## 8.2 Валидация

**Проблема.** Недоверенный ввод приходит из двух источников: пользователь и ответы Gemini. Часть правил статична, часть зависит от других полей.

**Решение.** Три уровня: `base/rules` (чистые правила) → `annotation` (декларативно) и `complex` (процедурно). Общий нижний уровень гарантирует одинаковое поведение правила в обоих способах. Ошибки накапливаются, а не прерывают проверку на первой.

**Правила:**

* статичное правило — аннотацией, зависящее от других полей — комплексной валидацией;
* новое правило сначала в `base/rules`, потом подключается к обоим способам;
* у каждого правила есть текст по умолчанию и возможность кастомного;
* ответ AI проходит ту же валидацию, что и ввод пользователя.

## 8.3 Обработка ошибок

**Проблема.** Ошибка возможна на любом слое; ответ клиенту должен быть предсказуемым, внутренние детали — не наружу.

**Решение.** Единая иерархия с корнем `AppException` (`domain`): `getErrorCode()`, `getLogLevel()`, `getTimestamp()`. На границе HTTP `HttpStatusResolver` отображает код в статус, `ErrorMapper` логирует и формирует `ErrorResponse`.

Разделение: `AppException` → сообщение уходит клиенту как есть; всё остальное → `500` и обезличенное `"Internal server error"` (это обслуживает QG-01).

**Правила:**

* ожидаемая ошибка — наследник `AppException` со своим `errorCode`;
* сообщение `AppException` пишется для пользователя API и уходит клиенту дословно;
* новый `errorCode` добавляется в таблицу `HttpStatusResolver`, иначе молча станет `500`;
* дополнительные данные раскрываются явно (сейчас — только поля `ValidationException`).

> **Компромисс.** `AppException` в `domain` импортирует `org.slf4j.event.Level`. Принято осознанно: SLF4J — фасад, уровень логирования считается частью смысла ошибки.

> **Открытый вопрос.** `DatabaseException` из `infrastructure` наследуется от доменного `AppException`. Правило не сформулировано — см. раздел 11.

## 8.4 DI и жизненный цикл

**Проблема.** Без фреймворка (LC-02) нужен собственный способ собирать граф объектов.

**Решение.** `DIContainer` с областями `SINGLETON` и `PROTOTYPE`, внедрение через конструктор (`@Inject`), обнаружение циклов. `Main` — composition root, запуск в три фазы: регистрация → создание графа (пул, миграции) → проверки и старт.

**Правила:**

* к контейнеру обращается только composition root и его помощники (`ControllerRegistrar`) — запрет Service Locator;
* зависимости внедряются через конструктор;
* конкретные реализации интерфейсов известны только в `Main`;
* освобождение ресурсов — в shutdown hook.

> **Открытый вопрос.** Часть объектов создаётся контейнером, часть — вручную через `new` в `Main` (`Router`, `ErrorMapper`, `RetryableTransactionManager`, `UserJdbcRepository`). Разделение сложилось стихийно. См. раздел 11.

## 8.5 AI Assistant

**Проблема.** Ответ AI — недоверенные данные, а AI должен читать и менять данные пользователя.

**Решение.** AI только предлагает, сервер проверяет и исполняет. Подробно — [concepts/ai-assistant/](concepts/ai-assistant/README.md).

**Правила:**

* запись идёт через те же сценарии, что и ручной API;
* создание — сразу, изменение и удаление — только по согласию на каждую операцию;
* данные — только из закрытого каталога, только текущего пользователя, без скрытых наград;
* без согласия на использование данных AI недоступен;
* лимиты — в конфиге с дефолтами.

## 8.6 Аутентификация

**Проблема.** Без входа системой пользоваться нельзя (AR-05), а токен в браузере можно украсть.

**Решение.** Access — JWT на 15 минут, refresh — случайный токен с ротацией, оба только в HttpOnly-cookie. Подробно — [concepts/authentication.md](concepts/authentication.md).

**Правила:**

* маршрут закрыт по умолчанию, открытый помечается `@Public`;
* id пользователя — только `ctx.userId()`, никогда из тела или параметров запроса;
* токены не попадают в тело ответа и в логи.
