# AI API

AI-ассистент текущего пользователя. Все маршруты требуют входа. Общие правила и ошибки — [README.md](README.md). Архитектура — [concepts/ai-assistant/](../architecture/arc42/concepts/ai-assistant/README.md).

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | [/ai/consent](#get-aiconsent) | Дано ли согласие на использование данных |
| POST | [/ai/consent](#post-aiconsent) | Дать согласие |
| POST | [/ai/requests](#post-airequests) | Отправить сообщение AI |
| GET | [/ai/requests](#get-airequests) | История запросов |
| GET | [/ai/requests/{id}](#get-airequestsid) | Один запрос |
| POST | [/ai/requests/{id}/execution](#post-airequestsidexecution) | Исполнить отмеченные изменения и удаления |
| POST | [/ai/requests/{id}/rejection](#post-airequestsidrejection) | Отклонить все изменения и удаления |

Все `/ai/requests*` без согласия отвечают `403 AI_CONSENT_REQUIRED`, и данные к провайдеру не уходят.

> **Провайдер включается конфигом.** По умолчанию `AI_PROVIDER=none`: `POST /ai/requests` записывает запрос и отвечает `503 AI_PROVIDER_UNAVAILABLE`. Для Google Gemini задайте `AI_PROVIDER=gemini`, `AI_MODEL` и `GEMINI_API_KEY` (только env или `.env`) — см. `.env.example`.

## Согласие

Даётся один раз и действует бессрочно; отозвать нельзя. Покрывает чтение всех категорий данных, которые может запросить AI: задачи, проекты, награды (кроме скрытых), рефлексия, планы, цели. Это **не** подтверждение операций: изменения и удаления AI подтверждаются в каждом предложении отдельно.

Текст окна согласия показывает фронтенд. В нём должно быть: какие данные читает AI, что они передаются Google Gemini, что тариф бесплатный и Google может использовать данные по своим условиям.

```json
{ "accepted": true, "acceptedAt": "2026-10-11T12:00:00Z" }
```

`acceptedAt` — `null`, если согласия нет.

## Запрос к AI (ответ)

```json
{
  "requestId": "7f9e…",
  "status": "ANSWERED",
  "summary": null,
  "answer": "Чаще всего просрочены задачи по грамматике",
  "clarificationQuestion": null,
  "errorCode": null,
  "refusalReason": null,
  "report": [],
  "pendingApproval": [],
  "dataAccessed": [ { "query": "LIST_TASKS", "items": 12, "reason": "Найти просроченные задачи" } ],
  "expiresAt": null,
  "createdAt": "2026-10-11T12:00:00Z"
}
```

| `status` | Что значит | Заполнено |
|----------|------------|-----------|
| `PENDING_AI` | AI ещё отвечает | — |
| `ANSWERED` | Текстовый ответ, ничего не изменено | `answer` |
| `EXECUTED` | Всё исполнено: AI предложил только создания (они не требуют подтверждения), или пользователь подтвердил хотя бы одно изменение или удаление | `summary`, `report`, по желанию AI — `answer` |
| `PROPOSED` | Создания уже исполнены, изменения и удаления ждут подтверждения до `expiresAt` | `summary`, `report`, `pendingApproval`, `expiresAt` |
| `REJECTED` | Пользователь отклонил все изменения и удаления; созданное осталось | `report` |
| `EXPIRED` | Не решено за 24 часа (`AI_PLAN_TTL_HOURS`) — изменения и удаления не исполнены | `report` |
| `NEEDS_CLARIFICATION` | AI задал вопрос. Истории диалога нет: дополните исходный текст и отправьте новый запрос | `clarificationQuestion` |
| `FAILED` | Не удалось — см. код | `errorCode`; для отказа ещё `refusalReason` |

### Что прочитал AI (`dataAccessed`)

AI сам запрашивает нужные данные из закрытого каталога: цели, проекты, задачи, награды (**кроме скрытых**), планы, ответы рефлексии — только этого пользователя, не больше 2 раундов. `dataAccessed` — журнал: какой запрос, сколько элементов отдано и зачем AI их просил. Содержимое не хранится. Пусто — AI ничего не читал.

ID сущностей AI не видит — только временные дескрипторы на время запроса. С ними AI может добавлять новые проекты и задачи в **существующие** цели и проекты (они не попадают в отчёт: создаются только новые).

### Карточка подтверждения (`pendingApproval`)

Изменения и удаления, которые предложил AI. Исполняются, **только если пользователь отметил их** — фронтенд показывает их с пустыми галочками. Названия — из БД, а не из текста AI; что именно изменится, не показывается — суть объясняет `summary`.

```json
"pendingApproval": [
  { "itemId": "u1", "op": "UPDATE", "type": "TASK",    "title": "Времена группы Simple" },
  { "itemId": "d1", "op": "DELETE", "type": "PROJECT", "title": "Старый" }
]
```

Заполнено только у `PROPOSED`. Что AI может менять: у задачи — название, описание, сложность, баллы, даты, проект, цель; у проекта — название, описание, срок, цель; у цели — название, описание; у награды (только видимой) — название, описание, стоимость. Статус, напоминание, скрытость — нет. За один запрос — не больше 20 изменений и 10 удалений (`AI_MAX_UPDATES`, `AI_MAX_DELETES`).

### Отчёт (`report`)

Что сделано. Строится сервером по фактическому результату, а не по тексту AI; деталей «было → стало» нет.

```json
"report": [
  { "itemId": "g1",       "result": "CREATED", "type": "GOAL",    "id": "1c9e…", "title": "Выучить английский" },
  { "itemId": "g1.p1",    "result": "CREATED", "type": "PROJECT", "id": "a41d…", "title": "Грамматика" },
  { "itemId": "g1.p1.t1", "result": "CREATED", "type": "TASK",    "id": "6b2f…", "title": "Времена Simple" },
  { "itemId": "r1",       "result": "CREATED", "type": "REWARD",  "id": "9f3a…", "title": "Кино" }
]
```

| Поле | Описание |
|------|----------|
| `itemId` | Место в плане: `g1` — цель, `g1.p1` — её проект, `g1.p1.t1` — задача проекта, `g1.t1` — задача цели, `p1`, `t1`, `r1` — проект, задача, награда без цели; `u1…` — изменения, `d1…` — удаления |
| `id` | ID сущности; `null` у удалённой |
| `result` | `CREATED`; после решения по карточке — ещё `UPDATED`, `DELETED`, `CANCELLED` (не подтверждено) |
| `type` | `GOAL`, `PROJECT`, `TASK`, `REWARD` — по `type` + `id` фронтенд строит ссылку |

Что создаёт AI: не больше 1 цели, 10 проектов, 10 задач в одном узле, 30 задач, 3 наград — всего 40 (`AI_MAX_*`). Награды — только видимые. Задачам назначаются стандартные вопросы рефлексии, как при ручном создании.

## POST /ai/requests

```http
POST /ai/requests
Idempotency-Key: 5b0c2c0e-9d1a-4c1e-a3a4-0d7d3c2c1f00

{ "message": "Какие задачи я чаще всего просрочиваю?" }
```

| Поле | Правила |
|------|---------|
| `Idempotency-Key` (заголовок) | Обязателен: 1–100 символов, `A-Z a-z 0-9 - _`. Новый на каждое новое сообщение; тот же — при повторе после таймаута |
| `message` | Обязательно, до 2000 символов (`AI_MESSAGE_MAX_LENGTH`) |

Сервер не хранит текст сообщения — только длину и хеш. Ответ AI может занять до 90 секунд.

**Ответ `201`** — запрос со статусом `ANSWERED`, `NEEDS_CLARIFICATION`, `EXECUTED` или `PROPOSED`.

**Повтор с тем же `Idempotency-Key`** — AI не вызывается снова: **`200`** с тем же телом или та же ошибка.

| Ошибка | Когда |
|--------|-------|
| 400 `VALIDATION` | Нет заголовка, пустое или длинное сообщение |
| 403 `AI_CONSENT_REQUIRED` | Нет согласия |
| 409 `AI_REQUEST_IN_PROGRESS` | Ещё обрабатывается этот или другой запрос пользователя (одновременно — один) |
| 429 `AI_QUOTA_EXCEEDED` | Лимит пользователя: больше 3 запросов в минуту, 20 в сутки или 200 созданий через AI в сутки (`AI_USER_REQUESTS_PER_MINUTE`, `AI_USER_REQUESTS_PER_DAY`, `AI_MAX_CREATED_PER_DAY`). Если план AI создал бы больше, чем осталось, ничего не создаётся |
| 422 `IDEMPOTENCY_KEY_REUSED` | Тот же ключ, другое сообщение |
| 422 `AI_REFUSED` | AI отказался: не про цели и задачи или операция недоступна для AI (например, «выполни задачу»); или провайдер заблокировал запрос своими правилами безопасности — переформулируйте |
| 422 `AI_PLAN_TOO_LARGE` | AI предложил больше, чем разрешено лимитами. Ничего не создано — сузьте запрос |
| 409 `TARGET_CHANGED` | Сущность, которую AI предложил изменить, изменилась, пока AI отвечал. Ничего не создано |
| 422 `BUSINESS_RULE_VIOLATION` | Предложение нарушило правило домена при исполнении. Ничего не создано |
| 502 `AI_INVALID_RESPONSE` | AI дважды ответил не по контракту |
| 503 `AI_PROVIDER_UNAVAILABLE` | AI недоступен или временно ограничил запросы |
| 503 `AI_PROVIDER_QUOTA_EXHAUSTED` | Бесплатная квота провайдера исчерпана. Следующие 60 минут (`AI_QUOTA_BREAKER_MINUTES`) новые запросы получают эту ошибку сразу, без обращения к AI |
| 504 `AI_TIMEOUT` | AI не ответил за 90 секунд (`AI_REQUEST_TIMEOUT_MS`) |

**Лимиты.** Окна скользящие: последняя минута и последние 24 часа. Считаются все записанные запросы, в том числе завершённые ошибкой; повтор с тем же `Idempotency-Key` и запросы, отклонённые до записи, — нет. Созданное через AI считается, даже если его потом удалили. У `429` и `503 AI_PROVIDER_QUOTA_EXHAUSTED` — `extension.retryAfterSeconds` и заголовок `Retry-After`, когда срок известен:

```json
{ "errorCode": "AI_QUOTA_EXCEEDED", "message": "Лимит запросов к AI исчерпан, попробуйте позже",
  "extension": { "retryAfterSeconds": 42 }, "timestamp": "2026-10-17T12:00:00Z" }
```

Если сервер перезапустится во время ответа AI, запрос останется `PENDING_AI` и через 90 секунд будет считаться `FAILED` (`AI_TIMEOUT`) — следующий запрос пройдёт.

## GET /ai/requests

История, новые первыми. Параметры `limit` (1–100, по умолчанию 50) и `offset`.

**Ответ `200`:** `{ "items": [ запрос, … ] }`

## GET /ai/requests/{id}

**Ответ `200`** — запрос. `404` — нет такого запроса (в том числе чужой).
`PROPOSED`, срок которого истёк, показывается как `EXPIRED`.

## POST /ai/requests/{id}/execution

```json
{ "approvedChangeIds": ["u1", "u3"] }
```

| Поле | Правила |
|------|---------|
| `approvedChangeIds` | Обязательно; `itemId` из `pendingApproval`. Пустой список — отклонить всё |

Исполняются только отмеченные изменения и удаления, остальные получают `CANCELLED`. Всё — одной транзакцией: при любой ошибке ничего не изменено, запрос остаётся `PROPOSED` — можно снять галочку с проблемной операции или отправить новый запрос.

**Ответ `200`** — запрос: `EXECUTED` (или `REJECTED` при пустом списке), `report` дополнен. Повтор с тем же списком — **`200`** с тем же телом.

| Ошибка | Когда |
|--------|-------|
| 400 `VALIDATION` | Нет `approvedChangeIds` |
| 403 `AI_CONSENT_REQUIRED` | Нет согласия |
| 404 `NOT_FOUND` | Нет такого запроса (в том числе чужой) |
| 409 `REQUEST_STATE_CONFLICT` | Запрос уже решён по-другому или в нём нечего подтверждать |
| 409 `TARGET_CHANGED` | Сущность изменили или удалили после предложения. Ничего не изменено |
| 410 `PLAN_EXPIRED` | Прошло больше 24 часов (`AI_PLAN_TTL_HOURS`); статус становится `EXPIRED` |
| 422 `APPROVAL_INVALID` | В списке `itemId`, которого нет в `pendingApproval` |
| 422 `BUSINESS_RULE_VIOLATION` | Итог нарушает правило — например, сокращён срок проекта, а срок его задачи не перенесён. Ничего не изменено |

## POST /ai/requests/{id}/rejection

Тела нет. Ни одно изменение и удаление не исполняется; уже созданное остаётся — его можно удалить вручную.

**Ответ `200`** — запрос `REJECTED`. Повтор — `200` с тем же телом. Ошибки — как у `…/execution`, кроме `400` и `422`.
