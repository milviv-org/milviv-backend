# Planning API

Планы и календарь текущего пользователя. Все маршруты требуют входа. Общие правила и ошибки — [README.md](README.md).

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | [/plans](#post-plans) | Создать план |
| GET | [/plans](#get-plans) | Список планов |
| GET | [/plans/{id}](#get-plansid) | Один план |
| PUT | [/plans/{id}](#put-plansid) | Изменить |
| DELETE | [/plans/{id}](#delete-plansid) | Удалить |
| GET | [/calendar](#get-calendar) | Календарь за период |

Чужой план неотличим от несуществующего: `404 NOT_FOUND`.

## План (ответ)

```json
{
  "id": "5e0b…",
  "taskId": "6b2f…",
  "title": "Английский",
  "description": null,
  "planDate": null,
  "daysOfWeek": ["WEDNESDAY", "FRIDAY"],
  "timeFrom": "19:00:00",
  "timeTo": "20:00:00",
  "createdAt": "2026-10-11T12:00:00Z",
  "updatedAt": "2026-10-11T12:00:00Z"
}
```

У разового плана задан `planDate`, `daysOfWeek` — `null`. У повторяющегося наоборот. Повторяющийся план действует со дня создания (по дате UTC).

## Поля плана (запрос)

| Поле | Тип | Правила |
|------|-----|---------|
| `title` | string | Обязателен, до 255 символов |
| `description` | string | До 5000 символов |
| `taskId` | uuid | Задача пользователя или нет; чужая или несуществующая — `400`, поле `taskId` |
| `planDate` | date | `YYYY-MM-DD` — для разового плана |
| `daysOfWeek` | string[] | `MONDAY` … `SUNDAY` — для повторяющегося плана |
| `timeFrom`, `timeTo` | time | Обязательны, `HH:mm` или `HH:mm:ss`; конец позже начала |

Задаётся ровно одно из `planDate` и `daysOfWeek`, иначе `400`, поле `planDate`.

## POST /plans

Тело — поля плана. **Ответ `201`** — план.

| Ошибка | Когда |
|--------|-------|
| 400 `VALIDATION` | Поля не прошли проверку, задача не найдена |

## GET /plans

Разовые планы по дате, затем повторяющиеся.

| Параметр | Описание |
|----------|----------|
| `taskId` | Только планы этой задачи |
| `limit` | 1–100; по умолчанию 50 |
| `offset` | По умолчанию 0 |

**Ответ `200`:** `{ "items": [ план, … ] }`

## GET /plans/{id}

**Ответ `200`** — план. `404` — нет такого плана.

## PUT /plans/{id}

Заменяет все поля: не переданное необязательное поле очищается. Версии у плана нет — последнее сохранение побеждает.

**Перенос.** Если у плана задачи сменилась дата разового плана (задача та же), перенос записывается в историю: было → стало. Её используют статистика и AI-анализ.

**Ответ `200`** — план.

| Ошибка | Когда |
|--------|-------|
| 400 `VALIDATION` | Поля не прошли проверку, задача не найдена |
| 404 `NOT_FOUND` | Нет такого плана |

## DELETE /plans/{id}

**Ответ `204`.** История переносов остаётся. Планы задачи удаляются вместе с задачей.

| Ошибка | Когда |
|--------|-------|
| 404 `NOT_FOUND` | Нет такого плана |

## GET /calendar

Что происходит в каждый день периода. Даты — по UTC.

| Параметр | Описание |
|----------|----------|
| `from` | Обязателен, `YYYY-MM-DD` |
| `to` | Обязателен, `YYYY-MM-DD`, не раньше `from`. Период — не длиннее 62 дней (`CALENDAR_MAX_DAYS`) |

**Ответ `200`:**

```json
{
  "from": "2026-10-11",
  "to": "2026-10-17",
  "days": [
    {
      "date": "2026-10-14",
      "plans": [ план, … ],
      "taskDeadlines": [ задача, … ],
      "completedTasks": [ задача, … ],
      "projectDeadlines": [ проект, … ]
    }
  ]
}
```

| Поле дня | Что в нём |
|----------|-----------|
| `plans` | Разовые планы на эту дату и повторяющиеся на этот день недели, по времени начала |
| `taskDeadlines` | Активные задачи со сроком в этот день ([задача](tasks-api.md#задача-ответ)) |
| `completedTasks` | Задачи, выполненные в этот день |
| `projectDeadlines` | Активные проекты со сроком в этот день ([проект](projects-api.md#проект-ответ)) |

В `days` есть каждый день периода, в том числе пустые.

| Ошибка | Когда |
|--------|-------|
| 400 `VALIDATION` | Нет `from` или `to`, неверный формат, `to` раньше `from`, период длиннее предела |
